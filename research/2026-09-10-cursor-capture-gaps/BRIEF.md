# Cursor capture gaps: brief

Determine which supported or private interfaces can recover visible assistant messages, faithful tool arguments/results/status, stable identities, usage and history missing from native Cursor hooks. Editor and CLI have equal priority; ordinary use and passive recovery are preferred. Build on the existing controlled probes and current draft adapter, not a repeat of the original plugin study.

Deliver a cited, decision-oriented Markdown report with a coverage matrix and ranked implementation candidates. Distinguish actual observations, static source evidence, official documentation and hypotheses. Current clients: editor 3.19.19; isolated CLI 2026.09.08-6caf4ff. Freshness: September 10, 2026.

Scope includes editor storage/export/extension interfaces, CLI stream/ACP/persistence, specialized hooks, MCP and native network transport. Enterprise OTEL is established as metadata-only and is a comparison baseline. Exclude production implementation, global installation changes, unrelated conversation contents, credential extraction/copying, hidden reasoning capture and publishing. Previously authorized controlled model probes remain permitted; prefer free local inspection first.

Success means every promising path has a coverage, supportability, identity, privacy and resource-cost assessment, with the strongest recovery candidate tested on a known disposable session or its blocker precisely stated. Stop when remaining paths are speculative or require a materially different authorization boundary.
